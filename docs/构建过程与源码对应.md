# 构建过程与源码对应

## 教材结构视角

已有结构图不是接口重复生成的。以原项目发布指针指定的 v6 为准，保留原节点与来源标记。

| 原阶段 | 随包源码 | 可查看的过程 |
|---|---|---|
| MinerU 原树转段落实例、清理与来源保留 | `legacy_text_graph_tools/build_text_graphs.py`、`paragraph_cleaning.py`、`source_recovery.py`、`text_graph_assets.py` | 字段范围、正文库、图片与公式来源 |
| 证据修复 | `compile_evidence_plan.py`、`build_evidence_graphs.py`、`evidence_repair.py` | 修复计划、补丁与重建记录 |
| 物理出处与正文组织 | `build_physical_graphs.py`、`build_pdf_paragraph_graphs.py` | 原页、OCR 记录、来源跨度 |
| PDF 行像素与边界建议 | `extract_pdf_line_geometry.py`、`propose_pdf_boundaries.py`、`pdf_paragraph_rules.py` | 行几何、像素支持、边界判定 |
| 页码与章节归属修复 | `reconcile_pdf_sources.py`、`reconcile_heading_scopes.py`、`build_layout_ownership_v6.py` | 修复台账、归属依据、原页对应 |
| 书—章—节—小节—段落层级 | `build_hierarchy_view.py` | `hierarchy_graph.json`、层级清单 |
| 验收与发布 | `verify_*.py`、`publish_*.py` | 文件哈希、结构和来源验收、待核标记 |

当前 `build_structure` 封装的是原层级生成阶段：输入已有物理段落图，复制到全新输出目录后直接调用原 `build` 函数。`export_structure` 用于已经发布的图，只做来源核验与逐字节复制。两种入口均不调用模型。

历史全链条依赖原 PDF、MinerU 数据、v3/v4/v5 中间产物、审计与人工修复材料；若从原 PDF 重新复现完整 v6，需要保留这些输入。部分脚本带当时固定的版本路径，随包原样保留，不能把源码归档误解成任意 PDF 一键生成 v6。历史脚本应在保留原目录布局的研究副本运行，不能直接指向当前生产目录。可选 PDF 依赖见 `pyproject.toml` 的 `legacy-pdf`。

## 概念语义视角

```text
已发布结构图
  → source_adapter.prepare_source（哈希核验、读取原段落）
  → sources.prepare_corpus（证据切分、正文片段、相邻上下文）
  → IncrementalEngine.seed（独立生成 G0）
  → analyze / extract_graph（正文片段与当前局部图上的抽取）
  → ConceptIndex / SemanticMerger（嵌入召回、同义身份判断）
  → GraphStore 提交（证据校验、版本、去重、更新与历史）
  → complete_prior（必要的先验定向核查）
  → 在线及最终语义维护
  → graph.json / graph.sqlite / 可选 Neo4jProjection
```

源码位于 `domain_ckg_workspace/ckg_incremental/`。原文件未经重写，哈希见 `SOURCE_MANIFEST.json`，新增接口位于 `dual_kg/`。并非按名称直接合并；合成演示中的固定身份判断仅供无网络测试，不参与真实运行。

| 阶段 | 提示词 |
|---|---|
| G0 | `01_G0生成_system.txt` / `01_G0生成_user.txt` |
| 当前单次片段图抽取 | `06_片段图谱抽取_system.txt` / `06_片段图谱抽取_user.txt` |
| 语义身份判断 | `07_同义概念判定_system.txt` / `07_同义概念判定_user.txt` |
| 原分阶段概念、身份、更新与复核路径 | `00_教材共同_system.txt`、`02` 至 `05` 的对应文件 |

提示词目录：`prompts/incremental_v5/`。`runtime.ModelRuntime.FILES` 明确规定每阶段使用的实际文件。修复和格式校验仍走原 runtime，模型无效返回与失败尝试在原 SQLite 中保留，不能把模型输出直接视为人工确认。

每条教材证据通过 `source_id` 回到结构图段落，以 `start`、`end` 指示该段原文中的字符范围。来源信息及语义图断言构成现有跨视角连接；不额外声称论文规划的支持组、来源角色标注或问答模块已实现。

## 如何审阅中间处理

1. 先读 `corpus.json`，查看实际发送给引擎的来源片段。
2. 对照 `g0.json` 与 `analysis/*.json`，区分先验和教材提供的知识。
3. 查看 `decisions/*.json` 和 `graph.sqlite` 的 `events`、`claims`、`chunks`，核对最终提交。
4. 运行 `process-export`，按 `stage` 和 `status` 阅读 `model_attempts.jsonl` 中真实模型返回与失败尝试。
5. 查看 `run_state.json` 的失败计数、状态与 `human_accepted`，避免把程序结束当成人工质量确认。

公开分享过程文件前应单独整理允许分享的摘录，因为运行产物可能含教材原文；发布代码包本身不收录真实教材数据。
